# 多字幕源：接入与手动下载

## 当前支持

| 来源 | 获取方式 | 当前验证 | 使用条件 |
|---|---|---|---|
| Shooter | 本地视频指纹 | 2026-10-20 用公开历史指纹验证查询与下载；当前有效匹配已很少 | 旧版来源、默认关闭；启用后，指纹且零偏移的结果拥有最高自动选择优先级 |
| 迅雷 | HTTPS 文件名搜索 | 2026-10-19 实测搜索返回列表，个别 SRT 链接下载成功 | 无 Token；自动匹配后标记时间轴未经验证 |
| ASSRT | 官方搜索 → 详情 → 文件或压缩包下载 | 2026-10-20 已用真实视频验证搜索、详情、下载与 ASS 提取 | 用户自己的 32 位 Token，保存在应用偏好 |
| SubtitleBest | 暂未接入 | 调研时 API 探测超时 | 待核实当前服务、注册及授权 |
| A4K | 暂未接入 | 调研时网站 TLS 连接失败 | 待核实站点和访问规则 |

一次网络失败不代表网站永久不可用。迅雷接口没有公开稳定性承诺，当前可用也不保证长期兼容。
旧迅雷 CID 接口 HTTPS 探测失败，因此本轮没有启用它；文件名搜索返回的 `cid` 不能作为已验证的视频指纹匹配证据。

## 使用

1. 在设置中启用来源。默认只启用迅雷；Shooter 是旧版精确指纹服务，当前匹配稀少，需要时可手动启用。
2. 使用 ASSRT 时，从 [用户面板](https://assrt.net/usercp.php) 获取 Token，打开 ASSRT 开关后输入即可自动保存到应用偏好。输入框有内容时可使用下方按钮删除 Token。Token 不写入 URL 或日志，也不访问钥匙串。搜索词由视频文件名提取为“片名 + 年份/季集”，会去掉分辨率、编码、音轨和发布组等标签。
3. 主窗口选择一个视频，点击“搜索并选择字幕”。顶部搜索框默认使用视频文件名；可以编辑片名并按回车重新搜索。列表显示标题、来源、格式、语言（来源提供时）和偏移状态，搜索不写入文件。
4. 核对影片、年份、季集和语言后选择结果下载。成功状态显示在窗口左下角；切换候选后可继续下载。字幕保存在视频旁并更新队列状态；关闭窗口会取消未完成的任务，已成功保存的文件保留。关闭覆盖时，同格式的后续手动下载依次保存为 `影片名.1.srt`、`影片名.2.srt` 等，不覆盖已有文件。
5. 批量“下载待处理”搜索全部已启用来源。Shooter 指纹结果优先；文件名结果按片名、年份、季集和中文线索排序。
   年份或季集冲突会排除，没有足够匹配证据的结果留给手动选择。未知偏移可以自动下载，但结果会明确标记“时间轴未经验证”。
6. 迅雷按照本地文件计算 CID：小于 60 KiB 时计算全文 SHA-1，否则读取开头、约三分之一处和结尾各 20 KiB。
   返回 CID 与本地 CID 相同的候选视为指纹匹配；同一下载 URL 去重，随后按简体中文和来源评分排序，最多保留 20 项。
7. ASSRT 使用 `is_file=1` 对文件名搜索降噪，并将原始片名、适配视频名、归档名和内部字幕文件名一起用于匹配。
8. 片源版本只作为软评分：分辨率、BluRay/WEB-DL 等来源、H.264/H.265/AV1 编码和发布组相同会加分，
   不会因版本信息缺失而丢弃片名、年份与季集正确的字幕。来源评分被限制为较小的加分，不能压过身份匹配。

## 架构与边界

- `SubtitleProvider` 分离搜索与下载；`SubtitleSearchCoordinator` 每个视频最多并行查询两个来源，按注册顺序合并，以来源 + 引用去重。来源故障不丢弃其他结果。
- `MultiSourceSubtitleService` 提供自动下载和显式候选下载。应用在每次操作开始时读取设置，随后固定配置，避免途中改变来源。
- `SubtitleArchive` 调用系统 `bsdtar` 列出并流式读取压缩包成员，只保留安全的 ASS/SRT 路径，不把归档内容解压到视频目录。
- 迅雷与 ASSRT 的下载仅接受当前 Provider 实例签发的候选，防止随意替换引用。
- ASSRT 搜索请求带 `filelist=1`，优先展开其中的 ASS/SRT 文件。搜索页缺少文件清单时，下载阶段会重新请求详情并支持单个文件或压缩包；下载文件请求不携带 Token。
- ASSRT 进程内共享限流器，每次 API 请求间隔至少 3.1 秒，等待可取消。其他程序或设备仍可能共用 IP/Token 配额；API 非零状态与 HTTP 故障会显示为来源错误。
- ASSRT 的空列表兼容 `{}`、`[]`、null 和缺失字段。其文件主机只提供 HTTP 签名链接，因此仅对 `fileN.assrt.net` / `dlN.assrt.net` 放宽 HTTP，并发送必要的 `Referer` 和兼容 User-Agent；其他来源仍严格要求 HTTPS。
- ASSRT 压缩包通过系统 `bsdtar` 只读列出成员，再按候选格式提取，优先选择简体或双语条目；不把归档路径解压到视频目录。压缩包限制 32 MiB，单个字幕限制 8 MiB。文件主机偶发返回 503 时可重试。
- 手动下载限制 8 MiB，检查 SRT 时间行或 ASS Events/Dialogue 结构，支持 UTF-8、带 BOM 的 UTF-16 和 GB18030 并保存为 UTF-8。该检查是基本结构检查，不是完整语法解析或同步保证。
- 自动下载与手动下载使用同一内容校验和原子写入路径。自动匹配只能判断元数据是否一致，无法在下载前证明字幕时间轴同步。
- 原自动下载保持既有的大小、空内容、HTML 检查与覆盖规则。所有写入使用公共原子写入层，不从服务器文件名构造本地路径。
- 暂未实现自动评分、跨源内容去重、预览字幕正文、SSA/VobSub。候选名称核对由用户完成。

## 开发与验证

新增来源实现 `SubtitleProvider` 并注册；使用可注入 `HTTPTransport` 编写固定响应测试。
执行 `swift test`，再运行 `python3 Scripts/generate_project.py` 同步 Xcode 工程并构建。
测试覆盖 Token 校验/传递范围、业务状态错误、过期链接重新解析、拒绝伪造候选、取消限流等待、手动下载的未知偏移与文件保护、编码和内容检查。
真实服务验证与样本测试分开：ASSRT 已用带完整发布标签的真实视频完成端到端验证，旧查询返回 0 条，归一化查询返回候选，下载 ZIP 后成功提取并保存 ASS 字幕。样本测试覆盖查询归一化、HTTP 域名限制、Referer、压缩包提取和格式筛选；外部服务稳定性仍可能变化。

参考：[ASSRT 官方 API](https://assrt.net/api/doc)、[MeiamSubtitles](https://github.com/91270/MeiamSubtitles)、[ChineseSubFinder](https://github.com/ChineseSubFinder/ChineseSubFinder)。
